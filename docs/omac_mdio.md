# omac_mdio: MDIO master (clause 22 and clause 45)

**Maturity (v0.2.0-dev): simulated and implemented, not yet on hardware.** Self-checking
simulation against behavioural PHY models ([](#verification)), out-of-context implementation on
UltraScale+ and Versal at 100 and 250 MHz ([](#resources-and-timing)), Linux driver
compile-tested against the AMD linux-xlnx 6.12 kernel and mainline 6.17, bare-metal driver
unit-tested on the host.

`omac_mdio` is an MDIO master (the station management entity of IEEE 802.3) with an AXI4-Lite
register interface. It sends **clause 22** frames (read, write) and **clause 45** frames
(address, write, read, post-read-increment-address) to the PHYs on one MDC/MDIO bus. The omac
MACs, like many 10G and faster MAC cores, have no management interface of their own; omac_mdio
is the separate block that a design adds next to any MAC (an omac core, a vendor MAC, a hard
MAC) to manage its PHYs, typically several PHYs that need clause 45 management sharing one
bus. Written from scratch from IEEE 802.3 clauses 22.2.4.5 and 45.3; no third-party RTL.

* MDC from the register clock through a programmable divider (2.5 MHz from 100 MHz after
  reset), held low between frames or free-running.
* Full 32-bit preamble by default; any length 0-63 (0 = preamble suppression).
* One command at a time: a write to `CMD` starts it, `STATUS.BUSY` / `DONE`, read data in
  `RDATA`, optional level interrupt. A clause 45 access (address frame + data frame) is **one
  command** (`ADDR_FIRST`).
* No-answer detection (the turnaround bit a PHY must drive low), a readback check of every
  driven bit, abort with automatic resynchronisation of the bus.
* Hold-off: an input (and a register bit) that keeps new commands from starting, for example
  while the PHYs leave reset.
* Bit-bang mode: MDC and MDIO directly from register bits, for debugging.
* Tri-state outputs for an `IOBUF` (`mdio_i` / `mdio_o` / `mdio_t`), with an open-drain option.
* Ships with a **Linux MDIO-bus driver** and a **bare-metal driver** (unlike the MAC cores,
  which are driver-less by design: omac_mdio is a self-contained peripheral with its own
  registers).

## Architecture

| Module | File | Function |
|---|---|---|
| `omac_mdio` | `ip/omac_mdio/rtl/omac_mdio.sv` | registers, MDC generator, frame engine, sampling, outputs |
| `omac_sync_bit` | `common/` | synchronisers for `mdio_i` and `hold` |
| `omac_mdio_bd` | `ip/omac_mdio/rtl/omac_mdio_bd.v` | Verilog wrapper for IP integrator with interface attributes (generated by `scripts/gen_bd_wrapper.py`) |

Everything runs on one clock, the AXI4-Lite clock `clk`. The outputs (`mdc`, `mdio_o`,
`mdio_t`) come straight from flops. `mdio_i` passes `SYNC_STAGES` synchroniser flops; the
sample pipeline compensates their latency, so that the core samples MDIO at its pin at the
clock edge where MDC rises at the pin.

## Ports

| Port | Dir | Width | Description |
|---|---|---|---|
| `clk` | in | 1 | AXI4-Lite clock; also the time base of MDC |
| `rst` | in | 1 | synchronous reset, active high |
| `s_axil_*` | | | AXI4-Lite slave, 12-bit address (4 KiB window), 32-bit data; address and data are accepted together; every access answers OKAY |
| `irq` | out | 1 | level, active high: `STATUS.DONE` and `CFG.IRQ_EN` |

| `mdc` | out | 1 | MDC |
| `mdio_i` | in | 1 | MDIO from the pin (IOBUF `O`) |
| `mdio_o` | out | 1 | MDIO to the pin (IOBUF `I`) |
| `mdio_t` | out | 1 | 1 = release MDIO (IOBUF `T`) |

## Parameters

| Parameter | Default | Description |
|---|---|---|
| `DIV_INIT` | 19 | `CFG.DIV` after reset: MDC = `clk` / (2 (`DIV` + 1)); 19 gives 2.5 MHz from 100 MHz (49 for 250 MHz) |
| `PRE_INIT` | 32 | `CFG.PRE_LEN` after reset (0-63) |
| `OPEN_DRAIN` | 0 | 1: never drive MDIO high (`mdio_o` = 0, `mdio_t` = 1 for a 1); see [](#level-translators-and-open-drain-buses) |
| `SYNC_STAGES` | 2 | synchroniser flops on `mdio_i` and `hold` (2-4) |

## Register map

32-bit registers, byte addresses; reads of unused addresses return 0.

| Address | Name | Access | Description |
|---|---|---|---|
| 0x000 | `ID` | R | 0x4D44494F ("MDIO") |
| 0x004 | `VERSION` | R | 0x00000100 (1.0) |
| 0x008 | `CFG` | RW | configuration (below); reset 0x00002000 + `DIV_INIT` |
| 0x00C | `CMD` | RW | a write starts a command (below); reads the last command accepted |
| 0x010 | `WDATA` | RW | [15:0] data of a write frame or address of an address frame; [31:16] the register address of the `ADDR_FIRST` address frame |
| 0x014 | `RDATA` | R | [15:0] data of the last read frame; [16] `RD_VALID` |
| 0x018 | `STATUS` | R / W1C | status (below) |
| 0x01C | `CTRL` | W | [0] `ABORT`: write 1 to cancel the running or waiting command |
| 0x020 | `BITBANG` | RW | bit-bang mode (below) |

**`CFG`**

| Bits | Field | Reset | Description |
|---|---|---|---|
| 7:0 | `DIV` | `DIV_INIT` | MDC half period = `DIV` + 1 `clk` cycles |
| 13:8 | `PRE_LEN` | `PRE_INIT` | preamble bits before every frame (0 = suppressed) |
| 16 | `MDC_FREE` | 0 | 1: MDC runs continuously; 0: MDC is low between frames |
| 17 | `IRQ_EN` | 0 | `irq` = `STATUS.DONE` |
| 18 | `HOLD` | 0 | software hold-off, same effect as the `hold` input |

`DIV`, `PRE_LEN` are latched when a command starts; change them only while the core is idle.

**`CMD`**

| Bits | Field | Description |
|---|---|---|
| 1:0 | `OP` | the OP code of the frame as it goes on the wire: clause 22 `01` write, `10` read; clause 45 `00` address, `01` write, `11` read, `10` post-read-increment-address |
| 2 | `C45` | 0: clause 22 frame (ST = `01`); 1: clause 45 frame (ST = `00`) |
| 3 | `ADDR_FIRST` | clause 45 with `OP` != `00`: send an address frame with `WDATA[31:16]` first, then the frame of `OP`, back to back, as one command |
| 12:8 | `PHYAD` | PHY address (clause 22) / port address PRTAD (clause 45) |
| 20:16 | `REGAD` | register address (clause 22) / device address DEVAD, the MMD (clause 45) |

A write to `CMD` while `BUSY` = 1 (or in bit-bang mode) is ignored and sets `CMD_IGN`.
Clause 22 OP codes `00` and `11` are not defined by the standard; the core sends them as
write-type frames.

**`STATUS`**

| Bit | Field | Description |
|---|---|---|
| 0 | `BUSY` | a command is waiting or running |
| 1 | `DONE` | the last command has ended (completed or aborted); write 1 to clear; cleared by a new command |
| 2 | `RD_VALID` | the last command was a read and a PHY answered: `RDATA` is valid |
| 3 | `TA_ERR` | the last command was a read and no PHY drove the second turnaround bit low (no PHY at that address, PHY in reset, clause 45 frame to a clause-22-only PHY); `RDATA` holds what the bus read (0xFFFF with the pull-up) |
| 4 | `BUS_ERR` | a bit the core drove read back differently at its own pin (a PHY driving at the same time, a short); diagnostic |
| 5 | `ABORTED` | the last command was aborted |
| 6 | `CMD_IGN` | a `CMD` write was ignored; write 1 to clear |
| 8 | `HELD` | a command waits for the hold-off to end |
| 9 | `HOLD` | hold-off active now (`hold` input or `CFG.HOLD`) |
| 10 | `MDIO_IN` | MDIO at the pin (synchronised) |

`RD_VALID`, `TA_ERR`, `BUS_ERR` and `ABORTED` describe the last command and are cleared when the
next one starts.

**`BITBANG`**

| Bits | Field | Description |
|---|---|---|
| 0 | `MDC` | MDC level in bit-bang mode |
| 1 | `MDIO_O` | MDIO level driven in bit-bang mode |
| 2 | `MDIO_OE` | 1: drive MDIO; 0: release it |
| 8 | `MDIO_IN` | (read only) MDIO at the pin, synchronised |
| 31 | `BB_EN` | 1: MDC and MDIO follow the bits above; commands are ignored; setting it aborts a running command |

## Commands

| Operation | `WDATA` | `CMD` | Frames | MDC cycles (32-bit preamble) |
|---|---|---|---|---|
| clause 22 read | - | `0x0002` + PHY << 8 + REG << 16 | 1 | 65 |
| clause 22 write | data | `0x0001` + PHY << 8 + REG << 16 | 1 | 65 |
| clause 45 read | reg << 16 | `0x000F` + PRTAD << 8 + DEVAD << 16 | address + read | 130 |
| clause 45 write | reg << 16 + data | `0x000D` + PRTAD << 8 + DEVAD << 16 | address + write | 130 |
| clause 45 address | reg | `0x0004` + ... | 1 | 65 |
| clause 45 read (address set before) | - | `0x0007` + ... | 1 | 65 |
| clause 45 post-read-increment | - | `0x0006` + ... | 1 | 65 |

Sequence: write `WDATA`, write `CMD`, poll `STATUS` until `BUSY` = 0 (or wait for `irq`), check
`TA_ERR` for reads, read `RDATA`. A block of consecutive clause 45 registers is read with one
address command and one post-read-increment command per register.

## Frames and timing

Every frame is `PRE_LEN` preamble ones, the 32 frame bits, and one idle bit with MDIO released:

| | ST | OP | PHYAD / PRTAD | REGAD / DEVAD | TA | data / address |
|---|---|---|---|---|---|---|
| clause 22 read | 01 | 10 | 5 bits | 5 bits | Z 0 | 16 bits from the PHY |
| clause 22 write | 01 | 01 | | | 1 0 | 16 bits |
| clause 45 address | 00 | 00 | | | 1 0 | register address |
| clause 45 write | 00 | 01 | | | 1 0 | 16 bits |
| clause 45 read / post-read-increment | 00 | 11 / 10 | | | Z 0 | 16 bits from the PHY |

```text
MDC   ____/‾‾‾‾\____/‾‾‾‾\____/‾‾‾‾\____
MDIO  X====bit n====X===bit n+1==X=====      master drives: changes with the falling edge
            ^ PHY samples         ^          (setup and hold at the PHY = half an MDC period)
MDIO  ======X====bit k (PHY)====X========    PHY drives (read): changes after the rising edge,
       ^ master samples here    ^            master samples at the next rising edge
```

* **The master drives** MDIO with the falling edge of MDC, so setup and hold at the PHY are
  both half an MDC period (200 ns at 2.5 MHz; IEEE 802.3 asks for 10 ns each). Keep the half
  period at or above about 20 ns (`DIV` >= 1 at 100 MHz, >= 4 at 250 MHz) so board skew does
  not eat the 10 ns.
* **The PHY drives** read data after the rising edge of MDC (clause 22.3.4: 0 to 300 ns), and
  the core samples it at the next rising edge, at its own pin. The MDC period must therefore be
  longer than the PHY's clock-to-output delay plus the round trip (MDC out, MDIO back, level
  translators): with the standard 300 ns that is 2.5 MHz, the IEEE limit. Faster MDC is fine
  for PHYs whose data sheet allows it (shorter delay): for example 12.5 MHz (`DIV` 3 at
  100 MHz) needs a PHY output delay below about 60 ns.
* **MDC limits of the core:** `DIV` 0-255, MDC = `clk` / 2 to `clk` / 512 (50 MHz to 195 kHz at
  100 MHz; 125 MHz to 488 kHz at 250 MHz); the practical upper end is set by the PHY and the
  10 ns setup / hold as above.
* **Frame time** at 2.5 MHz: 26 us per frame (65 MDC cycles), 52 us per clause 45 access
  (130), plus a few `clk` cycles; with the preamble suppressed 33 / 66 MDC cycles.
* **Turnaround:** read-type frames release MDIO from the first turnaround bit to the end of the
  frame; the PHY must drive the second turnaround bit low, else `TA_ERR`. Write-type frames
  drive `1 0`.
* **Idle:** MDIO is released (`mdio_t` = 1) whenever no frame is driven; MDC is low, or running
  with `MDC_FREE`. Between two frames there is at least the idle bit.

| `clk` | `DIV` | MDC | half period |
|---|---|---|---|
| 100 MHz | 19 (reset value) | 2.5 MHz | 200 ns |
| 100 MHz | 3 | 12.5 MHz | 40 ns |
| 125 MHz | 24 | 2.5 MHz | 200 ns |
| 250 MHz | 49 | 2.5 MHz | 200 ns |
| 300 MHz | 59 | 2.5 MHz | 200 ns |

`DIV` = ceil(`clk` / (2 MDC)) - 1 gives the fastest MDC at or below the target.

### Preamble suppression

Clause 22 PHYs that report "MF preamble suppression" (register 1, bit 6) accept frames without
a preamble; many clause 45 PHYs accept them too (see the PHY's data sheet). With `PRE_LEN` = 0
the core sends only the idle bit between frames (33 MDC cycles per frame instead of 65). Send
the first frame after a reset (of the core or of a PHY) with the full preamble, and keep the
full preamble on a bus with a PHY that needs it: such a PHY ignores suppressed frames (and a
read to it ends with `TA_ERR`).

### Free-running MDC

`CFG.MDC_FREE` = 1 keeps MDC running while the bus is idle (MDIO released, so a PHY sees idle
ones). Frames then start at the next falling edge. Some PHYs want a continuous MDC (for example
to run their management logic); most do not care. The default is MDC low between frames.

### Hold-off (PHYs in reset)

While `hold` (or `CFG.HOLD`) is 1, no command starts: a command written during the hold-off
waits with `BUSY` = 1 and `HELD` = 1, without any bus activity, and starts when the hold-off
ends. A command that has started (including the data frame of an `ADDR_FIRST` command) always
runs to its end. Use it to keep software from talking to PHYs while they leave reset: drive
`hold` from the design's PHY reset logic, extended by the PHY's post-reset time. Software
that polls with a timeout should allow for the hold time (the Linux driver's `opsero,timeout-us`).
An aborted waiting command never reaches the bus.

### Abort and resynchronisation

`CTRL.ABORT` ends a waiting command at once (no bus activity) or stops a running frame: MDIO
is released immediately and MDC finishes its current high phase, so there is no glitch. A PHY
that was in the middle of the cut frame still counts bits (and may drive the bus for the rest
of a read). Therefore, after an abort of a frame that had started, the core puts **64 MDC
cycles with MDIO released** in front of the next frame: every PHY has finished the cut frame
(at most 31 more bits) and then sees at least 32 idle ones, a full preamble, before the next
frame. `DONE` and `ABORTED` are set. The drivers abort a command that does not finish within
their timeout.

### Bit-bang mode

With `BITBANG.BB_EN` = 1 the core's frame engine is disconnected and `mdc`, `mdio_o`, `mdio_t`
follow `BITBANG.MDC`, `MDIO_O` and `MDIO_OE` (open-drain mode applies); `BITBANG.MDIO_IN`
shows the pin. Software can then produce any waveform, for example to probe a PHY that does not
answer, or to emulate a non-standard frame. Each register write moves one edge (two to three
writes per bit, about 150 for a frame). A PHY drives read data after a rising edge: read `MDIO_IN` after
the following falling edge (as the Linux mdio-bitbang code does), and the value is the next
bit. Clear `BB_EN` to return to normal operation.

### Interrupt

`irq` = `STATUS.DONE` and `CFG.IRQ_EN`, level, active high; clear it by writing 1 to
`STATUS.DONE` (or by starting the next command). The Linux driver polls and does not use it.

## Integration

### In RTL

```systemverilog
wire mdio_i, mdio_o, mdio_t;
omac_mdio #(.DIV_INIT(19)) u_mdio (            // 100 MHz AXI clock -> 2.5 MHz MDC
    .clk(axi_clk), .rst(axi_rst),
    .s_axil_awaddr(...), /* ... AXI4-Lite ... */ .s_axil_rready(...),
    .irq(mdio_irq), .hold(phy_reset_hold),
    .mdc(phy_mdc), .mdio_i(mdio_i), .mdio_o(mdio_o), .mdio_t(mdio_t));
IOBUF u_mdio_buf (.I(mdio_o), .O(mdio_i), .T(mdio_t), .IO(phy_mdio));
```

Source list: `ip/omac_mdio/rtl/omac_mdio.f` (`common/omac_sync_bit.sv`,
`ip/omac_mdio/rtl/omac_mdio.sv`).

### In an IP integrator block design

Add the sources of `omac_mdio.f` and `ip/omac_mdio/rtl/omac_mdio_bd.v` to the project and
create the cell as a module reference:

```tcl
create_bd_cell -type module -reference omac_mdio_bd mdio_0     ;# VLNV xilinx.com:module_ref:omac_mdio_bd:1.0
set_property CONFIG.DIV_INIT 19 [get_bd_cells mdio_0]           ;# for a 100 MHz AXI clock
```

| Interface / pin | Type | Notes |
|---|---|---|
| `s_axil` | `xilinx.com:interface:aximm:1.0` slave, AXI4-Lite | connection automation works; 4 KiB address segment |
| `clk` | clock, `ASSOCIATED_BUSIF s_axil` | the AXI clock |
| `rst` | reset, active high | automation connects `proc_sys_reset/peripheral_reset` |
| `mdio` | `xilinx.com:interface:mdio:1.0` master (`MDC`, `MDIO_I`, `MDIO_O`, `MDIO_T`) | `make_bd_intf_pins_external` gives the ports `<name>_mdc` and `<name>_mdio_io`: the block design wrapper instantiates the `IOBUF` |
| `irq` | interrupt, level high | to the processor's interrupt input (or leave open) |
| `hold` | plain input | tie to 0 (`xlconstant`) or drive from the PHY reset logic |

(Checked in Vivado 2025.2 on a Zynq UltraScale+ block design: connection automation, address
assignment, validation, the generated wrapper with its `IOBUF`.)

### Pins and constraints

* MDIO needs a pull-up (IEEE 802.3 clause 22), normally on the board; the FPGA's
  internal pull-up (`PULLUP true`) is weak and only suits short buses.
* Set the I/O standard of the two pins for the bank voltage. No timing constraints are needed:
  the timing at the PHY is set by the MDC divider, not by the I/O delays (the ports show up as
  unconstrained in timing reports; `set_false_path -to [get_ports <mdc>]`, `-to/-from
  [get_ports <mdio>]` silence them).
* `hold` may come from any clock domain.

### Level translators and open-drain buses

* **Push-pull MDIO through an auto-direction (push-pull) level translator**, or no
  translator: the default (`OPEN_DRAIN` = 0). The core drives 1s and 0s and releases the bus
  for the PHY's bits.
* **Open-drain bus** (a pass-gate translator with pull-ups on both sides, or any bus where the
  master must not drive high): `OPEN_DRAIN` = 1. The core then drives only 0s (`mdio_o` = 0,
  `mdio_t` = 0 for a 0, 1 otherwise), the pull-ups make the 1s. The rising edges are RC slopes:
  choose the MDC rate so a 1 settles within half an MDC period (for example 1.5 kOhm and
  50 pF: about 90 ns to 70 %, fine at 2.5 MHz).
* **Split direction-controlled buffers** (separate in, out and direction pins): connect
  `mdio_o` to the buffer's input, the direction from `mdio_t` (1 = towards the FPGA; invert as
  the buffer needs) and `mdio_i` from its output.

## Software

### Linux

`ip/omac_mdio/drivers/linux/`: `omac_mdio.c` (MDIO-bus platform driver, `GPL-2.0-only OR
MIT`), `Kbuild`, `Makefile` (out-of-tree module), `opsero,omac-mdio.yaml` (device-tree binding).
It registers an `mii_bus` with clause 22 (`read` / `write`) and clause 45 (`read_c45` /
`write_c45`) accessors, so any MAC driver reaches its PHY through `phy-handle`, and the MDIO
core probes the PHY nodes below the bus node. Needs `CONFIG_PHYLIB` and `CONFIG_OF_MDIO`;
written against the AMD linux-xlnx 6.12 kernel, also builds on mainline (6.17 checked).

```
make -C ip/omac_mdio/drivers/linux KERNEL_SRC=<kernel build dir> ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
```

Device tree (two PHYs that need clause 45 management, at addresses 1 and 5, used by two MACs):

```dts
mdio0: mdio@a0010000 {
    compatible = "opsero,omac-mdio";
    reg = <0x0 0xa0010000 0x0 0x1000>;
    clocks = <&zynqmp_clk 71>;              /* the AXI clock (pl_clk0 here) */
    clock-frequency = <2500000>;            /* MDC, default 2.5 MHz */
    #address-cells = <1>;
    #size-cells = <0>;
    /* optional: suppress-preamble; opsero,mdc-free-running; opsero,timeout-us = <20000>;
     *           reset-gpios / reset-delay-us / reset-post-delay-us (MDIO core: PHY reset) */

    phy_a: ethernet-phy@1 {
        compatible = "ethernet-phy-ieee802.3-c45";
        reg = <1>;
    };
    phy_b: ethernet-phy@5 {
        compatible = "ethernet-phy-ieee802.3-c45";
        reg = <5>;
    };
};

&mac0 { phy-handle = <&phy_a>; };
&mac1 { phy-handle = <&phy_b>; };
```

Behaviour:

* one register write per access plus polling (10 us steps); a clause 45 access is one
  command (address + data frame), 52 us at 2.5 MHz;
* a read that no PHY answers returns 0xffff, which is what the MDIO core expects of an empty
  address when it scans for PHYs;
* a command that does not end within `opsero,timeout-us` (default 10 ms) is aborted and
  returns `-ETIMEDOUT`;
* with `clocks` the divider is set for `clock-frequency` (the fastest MDC at or below it);
  without `clocks` the core's reset divider (`DIV_INIT`) is kept;
* the bus is named after the device (`/sys/bus/mdio_bus/devices/a0010000.mdio:01`, ...).

### Bare metal

`ip/omac_mdio/drivers/baremetal/omac_mdio.[ch]` (MIT): polled, no interrupt, no dependency
beyond a 32-bit register read and write. The accessors default to `Xil_In32` / `Xil_Out32`
(AMD standalone BSP, MicroBlaze or Arm); define `OMAC_MDIO_RD32(addr)` and
`OMAC_MDIO_WR32(addr, val)` to use anything else.

```c
#include "omac_mdio.h"

omac_mdio_t mdio = {0};
uint16_t v;
if (omac_mdio_init(&mdio, MDIO_BASEADDR, 100000000, 2500000) != OMAC_MDIO_OK)
    /* no omac_mdio at that address */;
omac_mdio_c45_read(&mdio, 1, 1, 0x0002, &v);       /* PHY 1, MMD 1 (PMA/PMD), device identifier */
omac_mdio_c45_write(&mdio, 5, 7, 0x0000, 0x3200);  /* PHY 5, MMD 7 (auto-negotiation) control */
omac_mdio_c22_read(&mdio, 1, 1, &v);               /* clause 22 status register */
```

| Function | Description |
|---|---|
| `omac_mdio_init(m, base, clk_hz, mdc_hz)` | checks `ID`, aborts a leftover command, sets the divider (`clk_hz` 0: keep it), 32-bit preamble, MDC low between frames |
| `omac_mdio_c22_read/write(m, phy, reg, ...)` | clause 22 |
| `omac_mdio_c45_read/write(m, prtad, devad, reg, ...)` | clause 45, one `ADDR_FIRST` command |
| `omac_mdio_c45_read_inc(m, prtad, devad, reg, buf, n)` | n consecutive registers: one address frame, n post-read-increment frames |
| `omac_mdio_set_preamble / set_mdc_free / set_hold` | configuration |
| `omac_mdio_raw(m, cmd, wdata, &rdata)` | any command |
| `omac_mdio_div(clk_hz, mdc_hz)` | the divider for a target MDC |

Return codes: `OMAC_MDIO_OK`, `OMAC_MDIO_ERR_NORESP` (read not answered, value 0xFFFF),
`OMAC_MDIO_ERR_TIMEOUT` (not finished within `m->poll_max` status polls, default 1,000,000;
the command is aborted), `OMAC_MDIO_ERR_ID`, `OMAC_MDIO_ERR_ARG`. The host unit test
(`drivers/baremetal/test/`, `make drv-mdio`) runs the driver against a register model of the
core.

## Verification

`ip/omac_mdio/sim/tb_omac_mdio.sv` connects the core to three behavioural PHYs on one bus
(`tb_mdio_phy.sv`, written from clauses 22.2.4.5 and 45.3, not from the RTL): PHY 1 (clause 22
and 45, needs the full preamble), PHY 5 (clause 22 and 45, accepts preamble suppression), PHY 9
(clause 22 only) and nobody at address 7, with 5 ns of board delay each way and a PHY output
delay drawn per frame up to 300 ns (less at fast MDC). Every register written through the core
is mirrored by the testbench and checked on every read and in the PHY models' register files.
Continuous checks: MDC high / low times, MDIO setup and hold at the PHY (>= 10 ns), no bus
contention, MDIO released when idle, no driven 1 in open-drain mode. Covered: every OP of both
clauses, per-MMD address registers, `ADDR_FIRST`, post-read-increment (and its wrap), absent
PHYs, back-to-back commands and the exact frame time, `DIV` 1-255, preamble lengths 0 / 8 / 32,
free-running MDC, hold-off (input and register, abort while held, hold rising inside a frame),
12 aborts at random bits with resynchronisation, a complete clause 22 read in bit-bang mode, the
interrupt, a command while busy, the bus-error flag (MDIO shorted low), AXI corner cases and a
random soak, at 100 MHz (push-pull, 2 synchroniser stages) and 250 MHz (open-drain, 3 stages).
Six deliberate RTL mutations (write turnaround, late release, no resynchronisation, no idle
bit, turnaround not checked, sampling without latency compensation) are each caught. Results:
[](simulation.md).

Not yet covered: hardware, and the Linux driver on a running kernel (it is compile-tested
only).
